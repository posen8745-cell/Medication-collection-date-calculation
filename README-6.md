## 一、作品介紹

### 自主學習動機：從爸媽的工作需求出發

這項作品的起點不是競賽題目，而是**想幫爸媽解決工作上遇到的實際問題**。爸媽的工作情境中，會需要確認慢性病連續處方箋在某個日期是否已到下一次可領藥的時間。當處方開立日、第一次領藥日、第二次實際領藥日與藥品天數不同時，單靠心算或查看月曆，不容易快速釐清日期。

我想到自己正在學習 Python 的條件判斷與日期運算，便嘗試把這種需要反覆確認的日期問題整理成程式，之後再將工具製作成可在瀏覽器開啟的網頁。讓爸媽可以輸入日期，先取得**領藥時間的試算結果**，再與正式規定及實際處方紀錄核對。

製作過程也讓我理解，**程式能協助計算，卻不能代替藥師作專業判斷**。尤其遇到提前領藥、延後領藥、處方有效期限或春節特殊公告時，更需要把假設條件清楚告訴使用者。

### 自主學習目標

1. 將生活中的工作需求，轉換成明確的輸入、判斷條件與輸出結果。
2. 練習西元與民國日期轉換、日期加減及資料驗證。
3. 理解一般慢箋再次領藥的日期計算概念，以及提前或延後領藥對後續日期的影響。
4. 設計可直接使用的操作介面，並呈現計算明細供核對。
5. 學習將本機程式的想法轉為 GitHub Pages 靜態網站，讓家人更方便使用。

## 三、一般領藥日期的計算概念

### 1. 為什麼要看「上次用藥末日」？

慢性病連續處方箋再次調劑的一般規則，是依**上次給藥期間屆滿前 10 日內**判斷何時可再次調劑，而不是簡單以「已經過一半的天數」判斷。實際規定與個案適用情形，應以中央健康保險署資料及藥師確認為準。

這個網頁的基本計算概念為：

```text
本次試算最早領藥日 ＝ 上次累積用藥末日 − 10 天
```

系統還會檢查處方開立日、前次實領日與輸入的有效截止日等條件。程式中的公式是簡化的日期模型，**不表示所有慢箋都一定可在該日領取**。

### 2. 一般情境示範（每次 30 天）

假設第 1 次實際領藥日為 **2026/6/1**，每次領取 30 天：

| 計算項目 | 日期 | 說明 |
| --- | --- | --- |
| 第 1 次實領日 | 2026/6/1 | 開始用藥的示範日期 |
| 第 1 次用藥末日 | 2026/6/30 | 第 1 次給藥共 30 天 |
| 第 2 次試算起日 | **2026/6/20** | 6/30 往前 10 天 |
| 假設第 2 次實領日 | 2026/6/25 | 仍在第 1 次用藥期間內 |
| 第 2 次接續用藥末日 | 2026/7/30 | 第二批藥量接在 7/1～7/30 |
| 第 3 次試算起日 | **2026/7/20** | 7/30 往前 10 天 |

**重要觀念：** 提早拿到下一批藥，不代表前一批尚未用完的藥量被忽略。系統會將用藥天數接續計算。

### 3. 如果第 2 次延後領藥呢？

假設第 1 次藥量用至 6/30，但實際到 **7/5** 才領取第 2 次：

```text
第 2 次實領日：2026/7/5
第 2 次用藥末日：2026/8/3
第 3 次試算起日：2026/7/24
```

此例與前一個例子不同，因為第 2 次領藥時間已經晚於前次用藥末日。

### 4. 有效期限的重要性

使用者可以直接填入**處方箋標示的有效截止日**，程式會優先採用這個日期；若沒有輸入，網站才用「開立日＋自訂有效天數－1」作為**估計值**。

**不要把估計有效期限當成正式處方有效期限。** 若試算起日晚於輸入的截止日，網頁會提示該次在輸入期限內沒有有效領藥區間。

## 四、春節提前領藥情境

某些年度的春節假期，健保署會公告符合條件者可提早領藥。這類規則**不能直接當作每年固定不變**，所以本工具沒有把某年的公告永久套用到所有年份，而是提供手動設定欄位：

| 輸入欄位 | 作用 |
| --- | --- |
| 啟用春節提前規則 | 開啟／關閉春節情境試算 |
| 用藥末日適用起日 | 公告所指的適用日期範圍起日 |
| 用藥末日適用迄日 | 公告所指的適用日期範圍迄日 |
| 公告最早可提前領藥日 | 當年公告允許提前的起始日期 |

### 115 年（2026 年）春節示範

健保署公告：若上次給藥天數的末日落在 **2026/2/14～2026/2/22**，符合條件者可自 **2026/1/31（含）** 起提前領藥。這是特定年度的規定，並非永久固定規則。

點選網站中的「帶入春節範例」，可觀察特定情境下日期如何改變；正式使用前仍須確認適用年度、公告、處方內容與實領紀錄。

官方資料：[中央健康保險署｜慢性病連續處方箋提前 14 天領藥（115 年春節）](https://www.nhi.gov.tw/ch/cp-19611-54564-4126-1.html)

## 五、操作方法

1. 開啟 [慢箋領藥日計算網站](https://posen8745-cell.github.io/Medication-collection-date-calculation/)。
2. 輸入**處方開立日**；第 1 次實領日若未填，網站會暫時假設與開立日相同。
3. 輸入第 2 次實領日（如已發生）；若未填，網站會**假設第 2 次在試算最早日領藥**，並據此估算第 3 次起日。
4. 確認每次處方天數、處方箋標示的有效截止日，以及希望判斷的日期。
5. 如需測試春節情境，展開「春節提前設定」，依該年度官方公告輸入資料。
6. 選擇「病患模式」看重點日期，或使用「藥師模式」展開計算明細。
7. 按「計算日期」查看結果；如需留下紀錄，可使用「列印／存成 PDF」或「下載結果文字」。
8. 依實際領藥紀錄重新輸入，不要把假設日期誤認成已領藥紀錄。

**隱私提醒：** 網站不需要輸入姓名、身分證字號或健保卡號。若使用共用電腦，建議不要勾選「在這個瀏覽器記住輸入」，並在使用完畢後清除資料。

## 六、系統設計與技術原理

| 技術 | 在作品中的用途 |
| --- | --- |
| HTML | 建立處方日期、天數、模式與操作按鈕的表單 |
| CSS | 設計桌機／手機版介面、日期結果卡片與列印版面 |
| JavaScript | 驗證輸入、計算用藥末日、比較日期與更新畫面 |
| `Date` / UTC 日期計算 | 處理日期增減，避免單純用字串或月份數字相加 |
| `Intl.DateTimeFormat` | 以台灣時區取得預設判斷日期 |
| `localStorage` | 經使用者勾選後，保存部分輸入值於本機瀏覽器 |
| `window.print()` | 列印或由瀏覽器另存結果 PDF |
| `Blob` | 下載文字格式的試算結果 |
| GitHub Pages | 讓靜態網頁透過網址直接使用，不需安裝 Python |

### 日期計算流程（概念圖）

```text
輸入開立日／實領日／天數／截止日
                  │
                  ▼
            日期格式與順序檢查
                  │
                  ▼
          計算第 1 次用藥末日
                  │
                  ▼
       試算第 2 次最早領藥日期
                  │
                  ▼
       納入第 2 次實領或假設日期
                  │
                  ▼
         計算接續的用藥末日
                  │
                  ▼
       試算第 3 次最早領藥日期
                  │
                  ▼
   檢查截止日與春節設定 → 呈現結果
```

### 程式功能邊界

- 網站可輸入 1～365 天作日期運算，但**不代表這些數值都符合健保慢箋調劑規範**。正式用藥天數須以處方及適用法規為準。
- 「藥師模式」僅表示顯示較詳細的**計算明細**，不代表具備專業審核或與藥師資訊系統串接。
- 網站沒有儲存患者資料至雲端，也沒有使用健保署 API 進行即時資格查詢。

## 九、目前限制與後續可研究方向

### 目前限制

1. **只試算日期，不判定實際可領藥資格。** 不連線健保資訊系統或藥局系統。
2. 僅模擬**同一張處方、相同給藥天數、最多三次領藥**的主要情境。
3. 不處理換藥、改變劑量、特殊一次領取總藥量、藥品重複用藥審核等複雜狀況。
4. 未填第 2 次實領日期時，第 3 次結果含有**假設條件**，不能視為真實調劑紀錄。
5. 春節提前規則需依當年度公告設定，且不同身分或個案可能需要不同文件與核對。
6. 網頁允許自訂天數，但未完整檢核所有健保法規條件。
7. 本機保存僅限同一瀏覽器與裝置；共用裝置需注意輸入資料的保護。

### 未來可研究方向（目前未完成）

1. 增加更多測試案例，讓提前、延後及跨年日期的檢查更完整。
2. 依官方公告持續更新特殊假期的試算情境，並註明公告適用年份。
3. 改善手機顯示與提示文字，讓不熟悉程式的家人更容易理解結果。
4. 在不記錄個人身分資料的前提下，增加更清楚的「已確認／假設資料」區分。
5. 若要進一步應用於正式藥事流程，須由具專業資格者確認法規、資料安全、系統整合及測試標準。

### 學習歷程作品摘要

我製作「慢性病連續處方箋領藥日期試算工具」，起因是想協助爸媽處理工作中需要反覆確認領藥日期的需求。我先整理開立日、實領日、給藥天數與有效截止日之間的關係，再用程式試算第 2、3 次領藥的可能起日。遇到提前領藥時，程式會接續剩餘藥量；遇到延後領藥，則根據實際日期重算，並提供春節公告情境及日期明細。後來我將這個想法做成 GitHub Pages 網頁，讓家人不必安裝程式就能操作。這次自主學習讓我體會到，從生活問題出發設計工具，不只需要程式能算出答案，也要清楚標示假設與限制，避免把試算誤認成正式的藥事判定。

**最後提醒：本作品僅供自主學習及日期規劃示範。所有實際調劑、處方有效性與用藥問題，應依健保署最新規定、處方箋內容及藥師專業判斷辦理。**
